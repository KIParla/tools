= Changelog

This page tracks notable documentation and maintenance changes for the `tools` repository.

== Unreleased

* `tsv2vert_v2.py`: new derived `duration_range` conversation attribute (`0-15 min`,
  `15-30 min`, `30-60 min`, `60-90 min`, `90+ min`, `N/A`), computed from
  `duration` so the otherwise-continuous duration is usable as a filter and in
  charts (`DURATION_BANDS`). `generate_registry_draft.py` emits it.
* `translate_metadata.py`: `age-range`, `gender`, `birth-region` and
  `school-region` are open-vocabulary columns (`OPEN_COLUMNS`): only placeholder
  values (`_`, `over 85`) are mapped and unmapped values are not reported.
* `tsv2vert_v2.py`: the `participants` column of `conversations.tsv` is no
  longer dropped; it is written as a comma-separated multivalue
  `<conversation participants="BO026,BO020">` attribute (registries declare it
  `MULTIVALUE "1"`, `MULTISEP ","`), so whole conversations can be selected by
  participant. The per-turn `participant_code` remains for selecting a
  participant's own turns.
* `tsv2vert_v2.py`: in a run with several input files each conversation code is
  written once — the first input file that has it wins, and later duplicates are
  reported on stderr (`skipping duplicate conversation …`). Needed for the
  aggregated `KIParla` corpus, where `TOD2001`–`TOD2016` are in both `KIP` and
  `ParlaTO`. List the preferred module first.
* `tsv2vert_v2.py`: `module_for_code` now also maps `BXA/BZA` → `ParlaBZ`,
  `SBC/SBI` → `Stra-ParlaBO` and `STC/STI` → `Stra-ParlaTO`, so `full_conversation`
  and `report_url` point at the right module in the aggregate corpus. For a
  corpus whose NoSketch name differs from the module name (`StraParlaBO` vs
  `Stra-ParlaBO`) pass `--artifacts-module`.
* `translate_metadata.py`: values are stripped of leading/trailing whitespace
  before translation (a trailing space in `3-Technicians ` in a source table
  broke the lookup and leaked into the vertical file).
* `generate_registry_draft.py`: no longer excludes `participants`; it is
  emitted as a multivalue conversation attribute labelled "Partecipanti", and
  the draft no longer emits `NESTED 1` on `transcription_unit` (units never
  nest).

* `tsv2vert_v2.py`: each `<transcription_unit>` now carries a `report_url`
  attribute — a prefilled "open a GitHub issue about this turn" link targeting
  the conversation's module repository (`--issues-base-url`, default
  `https://github.com/KIParla`; pass `""` to disable). The corresponding
  `report_url` `MAXLISTSIZE "0"` attribute was added to the KIParla registry
  files.
* `tsv2vert_v2.py`: `--translations-dir` (auto-detected from a sibling
  `translations/` directory) adds a `translation` structure attribute to each
  transcription unit that has a translation-tier rendering, matched by
  `parent_tu_id`.
* `tsv2vert_v2.py`: token lines now carry `lemma` and `upos` as positional
  attributes 3–4 (from the source TSV, empty when absent), and each
  `<conversation>` gets `linguistic_annotation="yes"/"no"`. The KIParla
  registry files gained the matching `ATTRIBUTE lemma` / `ATTRIBUTE upos`
  positional entries, a `linguistic_annotation` conversation attribute, and
  that attribute in `SUBCORPATTRS`.
* `tsv2vert_v2.py`: short pauses (`(.)`) and non-verbal behaviour (`((…))`) are
  emitted as zero-width `<pause/>` / `<nvb descr="…"/>` tags instead of tokens,
  so they no longer break token adjacency (`the (.) dog` still matches
  `"the" "dog"`). Registries gained `STRUCTURE pause` and `STRUCTURE nvb`. A
  turn that is only pause/NVB keeps the marker but loses its (now empty)
  `<transcription_unit>` wrapper. A run of consecutive markers (across turn
  boundaries too) is collapsed to at most one `<pause/>` and one
  `<nvb descr="a; b">` — two same-type zero-width structures at one position
  would otherwise be dropped by the indexer. `nvb` `descr` keeps `_` for spaces
  (a registry `DISPLAYBEGIN` cannot render a value with spaces); the markers
  show in the concordance as `·(.)·` / `·((descr))·`. A word that was glued
  (`SpaceAfter=No`) to a now-removed marker no longer emits `<g/>`.
* `tsv2vert_v2.py`: a speaker with no `participants.tsv` row (`???`, `??`, an
  unlisted code) now gets every `participant_*` attribute set to `N/A` instead
  of unset (NoSketch was showing the `===NONE===` sentinel).
* `WORD_CORRECTIONS`: added `ceh` → `c(io)è` and `mmh` → `mhmh`. Each
  occurrence is reported as a `WORD_CORRECTIONS` warning like the existing
  interjection spellings.
* new `vert2eaf-layered` command (`tsv2eaf_layered.py`): renders a `.vert.tsv`
  to a layered ELAN `.eaf` with a per-speaker tier hierarchy named in the
  Toolbox/ELAN interlinear `<code>@<speaker>` convention — `ref@` (units) ▸
  `ft@` (translation), `tx@` (Jefferson), `tx_ortho@` (orthographic) ▸ `tok@`
  (tokens) ▸ `nvb@`, `sent_id@` (many-to-many syntactic-sentence link) and,
  with `--linguistic`, `lemma@ / pos@ / xpos@ / feats@ / dep@`. Empty leaf
  tiers are pruned; `--template` writes an `.etf` with the full tier set for
  every speaker. `process` now also emits both a plain (`eaf/`, one tier per
  speaker) and a layered (`eaf_layered/` + `<module>.etf`) rendering of every
  conversation, unless `--no-eaf`.
* reworked NVB/shortpause overlap handling into two clearly separated concerns:
** **Bracket-edge position** (`switch_NVB` in `normalize.py`): an NVB tag or
   shortpause `(.)` immediately after `[` or before `]` now *always* stays in
   place, unconditionally — `nvb_participates_in_overlaps` no longer has any
   effect here (the parameter was removed from `switch_NVB` and
   `validate_and_normalize`). Previously NVB was relocated out of `[...]`
   unless the flag was set; shortpause was already always kept.
** **Token-feature encoding** (`TranscriptionUnit.add_token_features` in
   `data.py`): NVB and shortpause tokens now correctly get an `overlaps`
   feature at all when they genuinely sit inside a matched overlap span —
   previously they were entirely invisible to the character-to-token mapping
   (every character of `((laugh))`/`(.)` is a bracket/dot marker, i.e. has no
   "form character" under that mapping's definition, so it silently never
   matched). Since NVB/shortpause can never be interrupted by `[`/`]`
   mid-marker (unlike ordinary tokens, which can straddle an overlap
   boundary mid-word), a char range doesn't mean anything for them either:
   detected via the token's own character span rather than the letters-only
   index, and rendered in the `overlaps` column as the sentinel `X(id)`
   (e.g. `((ride))` → `X(0)`) instead of a `cs-ce(id)` char range — same
   convention as their `upos` value. Every existing downstream consumer of
   this column (`tsv2tei.py`, `tsv2chat_bak.py`, `make_patch.py`) only ever
   extracts the id via `\((\d+)\)`, so `X(id)` is a drop-in match.
** **TU/clique-level participation** (`Transcript.check_overlaps` in
   `data.py`): removed the old step 6a that pruned every graph edge touching
   an NVB/shortpause-only TU *before* cliques were even built — that meant a
   genuinely annotated `[...]` overlap on such a TU (and its overlap partner)
   lost its match entirely and fell through to an `OVERLAPS:MISSING_TIME`
   error with a `"?"` placeholder instead of a real feature. Now every edge
   survives into clique-building regardless of token type, so an annotated
   NVB/shortpause overlap always gets matched and featured correctly.
   `overlaps.nvb_participates_in_overlaps` now controls exactly one thing:
   whether an *unannotated* overlap event involving only NVB/shortpause
   tokens counts as removable noise (`false`, default) or as a genuine
   overlap that should have been annotated (`true`, now an
   `OVERLAPS:MISSING_ANNOTATION` error). Shortpause is assimilated to NVB
   here, gated by the same toggle.
* added an Antora documentation component for `tools`
* documented the standalone scripts with concrete command examples
* documented the test workflow
* added unit tests for the importable script logic
* refactored `tsv2eaf.py` so it can be imported and tested safely
