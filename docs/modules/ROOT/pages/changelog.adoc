= Changelog

This page tracks notable documentation and maintenance changes for the `tools` repository.

== Unreleased

* **`ContainsVariation` is only written when `Yes`.** The `code_variation` column of an ordinary token is `_`
  (it was `ContainsVariation=No`, 600 000+ rows per module with nothing to say). `ContainsVariation=No` in an
  older file is read the same. `tsv/` files of the modules have to be migrated: `ContainsVariation=No` is removed,
  `ContainsVariation=No|Nonce=Yes` becomes `Nonce=Yes`.
* **KIPasti: `#word` is a word of another code.** `variation_markers.hash_token` is on in `configs/KIPasti.yml`
  (`Code=Other`, `Language=NO_ISO_CODE`), as in the Stra modules.
* **Fix — the aggregate `KIParla` corpus no longer writes the `#`, `#*` and `$` markers.** They stand for the
  `variety` and `nonce` attributes, which the aggregate leaves out (it keeps only what every module has), but
  `tsv2vert.py` still prefixed the words with them. With `--common-attrs-of` the word is now written bare when the
  attribute is not kept. A `#`/`$` that the module's config does not recognise (a `#word` typed `error` in KIPasti,
  ParlaTO and Stra-ParlaTO: 90 tokens) is cut as well.
* **Derived repositories are regenerated locally.** New `regenerate_local.py` rebuilds KIParla-collection and
  KIParla-NoSketch-Data from the released modules in one pass and pushes only on request. The release-triggered
  GitHub workflows are removed: with several modules released together their pushes were rejected.
* **Sync from the `.eaf` keeps the ids and the tsv-only annotations.** `sync.py --from-eaf` no longer replaces
  `tsv/X.vert.tsv`: the new file is reconciled with the existing one (new `reconcile.py`). `tu_id`, `token_id`,
  overlap group numbers, `lemma`/`upos`/`xpos`/`feats`/`deprel`/`meta_label` and `Language=` survive an `.eaf` edit;
  new units and tokens get fresh ids. Before this, 243 of the 512 conversations got different ids on a round trip.
* **The layered `.eaf` is the editable file.** `tsv2eaf_layered.py` writes the `tu_id` in `ref@`, the right MIME
  type for the audio, and does not rewrite a file that would only change its date; new `eaf_layered.py` reads
  `ref@`/`tx@`/`ft@` back (`tx@` is the only text read). `sync.py --from-vert` writes the layered layout by default
  (`--layout flat` for the old one), `--from-eaf` reads both. By default only `ref@`, `tx@` and `ft@` are written: the
  derived word-level tiers (`tx_ortho@`, `tok@`, `nvb@`) are 6-7 times larger and are only written with `--words`
  (`sync.py --from-vert --words`, `vert2eaf-layered --words`). New page "The ELAN file".
* **Fix — `switch_symbols` moved intonation marks across letters and brackets.** The pattern `[:-~]` is a range of
  characters (`:` to `~`, which includes `< > [ ] =` and every lowercase letter), not the three characters
  `: - ~`. It rewrote `n.ove` as `no.ve`, `[h.]` as `[h].` and `telefono?<]` as `telefono<]?` whenever a unit was
  normalized.
* **Fix — `check_spaces` split an inhalation `.h` from its space.** `word .h` became `word. h`: a spurious dot on
  the previous word and a bare `h` token.
* **`((P))` is written as the short pause `(.)`** (rule `PAUSE_LABEL`).
* **New config `nonverbal_tokens.inhalation`** (default `false`, `true` in `configs/ParlaBZ.yml`): a standalone
  `.h` / `.hh` is classified `nonverbalbehavior` instead of `linguistic`, text unchanged.
* `serialize.py`: `Begin=`/`End=` no longer print float noise (`1602.7305000000001`).
* **`original/` is only for the first generation; later corrections start from `eaf/`.** The transcribers'
  files in `<module>/original/` are now an untouched archive; after the first generation the editable
  source is `eaf/X.eaf`, synced with `sync.py --from-eaf eaf/X.eaf`. `sync.py --from-eaf` on an
  `original/` file whose `tsv/` already exists prints a warning. The release guide and the README say so.
* **Breaking (NoSketch) — Italian attribute values, `contains_code_variation`, and an aggregate with
  only the attributes common to all modules.** `tsv2vert.py` now writes the yes/no values of the
  NoSketch attributes in Italian (`sì`/`no`: `unknown_participant`, `linguistic_annotation`,
  `contains_code_variation`, `nonce`) and the `variety` values as `altro`/`incerto`/`non specificato`.
  The unit attribute `contains_variation` is renamed `contains_code_variation` (label "Contiene
  variazione di codice"); it is written on every unit (`sì`/`no`) of a corpus that marks code
  variation, and not at all in one that does not (KIP, ParlaBZ), so it never shows as `===NONE===`.
  The aggregated `KIParla` corpus only offers what every module offers: new `registry_attrs.py` reads the
  module registries, `tsv2vert.py --common-attrs-of REGISTRY` (repeatable) keeps only those attributes
  in the vertical, and `registry_attrs.py prune` does the same for the aggregate registry (including
  `SUBCORPATTRS`). `variety` and `nonce` are never offered by the aggregate.
  New `registry_attrs.py level REGISTRY` gives the *annotation level* of a corpus (0 base, 1 with code
  variation, 2 with translation), which the regeneration workflow writes in the registry `INFO`.
* **Breaking — `code-variation` column renamed `code_variation`, `Volume` values capitalised.** All
  column names of the vert.tsv are now underscore-separated (`token_id`, `tu_id`, `meta_label`,
  `jefferson_feats`, `code_variation`); the hyphenated spelling was the only exception. The CSVW
  schema, the TEI mapping and the docs follow. `Volume=low`/`Volume=high` are now `Volume=Low`/`Volume=High`,
  like every other feature value (`jefferson_feats.py` and the module READMEs already described them
  that way). Files with the old column name are refused with an "old-format vert.tsv" error instead of
  being read as if they had no variation.
* **Breaking — `topic`, `participants-relationship` and `moderator` removed from the conversation
  metadata.** The three columns are no longer part of `metadata/conversations.tsv`, the CSVW
  conversations schema, the merged collection table, the corpus explorer (filters, colour-by and CSV
  export) or the metadata box of the HTML/PDF artifacts. In the TEI export a `moderator` role is now
  assigned from the speaker code (`R` as third character) in `semistructured-interview`
  conversations, since the `moderator` flag is gone.
* **Breaking — `variation` column renamed `code-variation`, feature `Variety` renamed `Code`.** The
  column of the vert.tsv that holds the variation features is now `code-variation`, and its
  token-level feature is `Code=` instead of `Variety=`. The values are renamed with it:
  `Variety=Other` -> `Code=Other`, `Variety=Unassignable` (`#*word`) -> `Code=Unsure` (the code can
  be assigned to more than one language), `Variety=Unsure` (tokens of a `# ` unit) ->
  `Code=Underspecified`. `ContainsVariation`, `Language=` and `Nonce=` are unchanged. The dataflags
  enum `tokenvariety` follows (`other`, `unsure`, `underspecified`) and the NoSketch positional
  attribute `variety` now carries `other`/`unsure`/`underspecified` (its name is unchanged). The
  tools refuse to read files with the old `variation` column (`variety.iter_vert_rows`); all
  modules were migrated and `csv-metadata.json` regenerated.
* New `build_explorer.py`: builds the corpus explorer (`KIParla-artifacts/explorer/index.html`), a single HTML
  page to filter the conversations by metadata, speaker attributes and measured features, see figures for the
  resulting sub-corpus and export it (code list, CSV, JSON, copy script). Reads the snapshots of the summaries repository.
* Removed the legacy `tsv2eaf.py` and its tests. It read the old column names `iu_id` / `iu_align` and
  failed on every current `.vert.tsv`; use `cli.py vert2eaf` (or `sync.py --from-vert`). The
  `regenerate-derived` workflow of the modules now calls `cli.py vert2eaf`.
* New `summarize.py`: per-conversation summaries and a module-level `snapshot.json` in
  the new `KIParla-summaries` repository, one folder per module (token counts by type, speaking time and token/time rates per speaker, overlap
  shares by time and by annotated tokens, variation). Run by hand; `--check` flags stale summaries.

* New `audio_check.py` and pipeline check: the end of each transcript's last annotation is compared with the
  length of its recording (audio file measured with `ffprobe` when `--audio-dir` is given, else `duration` from
  `conversations.tsv`). `AUDIO_OVERRUN` (annotations end after the audio) and `AUDIO_UNDERRUN` (they end well
  before it) are warnings, with thresholds in the new `audio_check` block of `configs/defaults.yml`. Run
  automatically by `sync.py --from-eaf` and `cli.py process` (new `--audio-dir`), recorded as `AUDIO_CHECK` in
  `summary.json`, and shown in a new *Audio length* section of each module's validation page. On Stra-ParlaBO
  it flags SBCB002 (transcript ends 14 min before the audio) and, on the old metadata, would have caught the
  swapped SBCA003/SBCA004 durations and SBIC011.

* **Breaking — vert.tsv variation format.** The `variation` column now holds *all*
  variation features of a token as one feature list (`ContainsVariation=Yes|No` for the
  unit, then `Variety=Other|Unassignable|Unsure`, `Language=<code>`, `Nonce=Yes`), instead
  of one unit-level label (`none`/`yes`/`unspecified`/`all`). `Variation=Token|Doubtful|Emerging`,
  `Orthography=Yes` and `Language=` leave `jefferson_feats`:
  `#word`/`#_` -> `Variety=Other`, `#*word` -> `Variety=Unassignable`,
  tokens of a `# ` unit -> `Variety=Unsure`, `$word` -> `Nonce=Yes`. The unit-initial
  `# ` / `#_ ` marker is now part of the first token's `span`, so every marker can be
  rebuilt from spans alone and `vert2eaf` is lossless for all of them. See
  xref:variation-format.adoc[Variation labels in the vert.tsv] for the full mapping. The
  tools **refuse to read old-format files** (`variety.iter_vert_rows`): regenerate every
  module with `sync.py --from-eaf` before using `tsv2formats`, `vert2eaf`,
  `linear2html`, `tsv2vert` or `tsv2tei`. Each released module needs a major version when
  regenerated; `csv-metadata.json` must be regenerated for every module
  (`csvw/generate_csvw.py`).
* NoSketch export (`tsv2vert.py`): positional `variation` and `non_standard_form` are now
  `variety` (`other`/`unassignable`/`unsure`) and `nonce` (`yes`); the unit attribute
  `language_variation` is now `contains_variation`. The `word` keeps its `#`/`#*`/`$`
  prefix. The `KIParla-NoSketch-Data` registries and docs use the new names; every corpus
  has to be rebuilt together with its registry.
* A `#_` marker anywhere in a unit now means "non-Italian from this point to the end of
  the unit" (a unit-initial one still covers the whole unit); `[#_ w]` is rewritten to
  `#_ [w]` (`HASH_UNIT_SPACE`, previously a config flag with no code behind it). Pauses,
  non-verbal tags, anonymized names and `xxx` inside the stretch keep their own type.
  Units starting with `#_` now also record their overlap spans.
* All tools read UTF-8 (BOM tolerated) and write UTF-8 without BOM, LF line endings,
  Unicode NFC (`textutil.py`). `csv` writers no longer emit CRLF.
* `sync.py --from-vert` accepts `--audio-ext` (e.g. `mp3`); the rebuilt EAF links audio by
  relative path and no longer carries an empty `default` tier. `sync.py` refreshes only the
  synced module's validation page.
* `generate_validation_report.py` writes one page per module
  (`validation-<module>.adoc`) plus an index (`validation.adoc`).

* `tsv2vert_v2.py`: new derived `duration_range` conversation attribute (`0-15 min`,
  `15-30 min`, `30-60 min`, `60-90 min`, `90+ min`, `N/A`), computed from
  `duration` so the otherwise-continuous duration is usable as a filter and in
  charts (`DURATION_BANDS`). `generate_registry_draft.py` emits it.
* `translate_metadata.py`: `age-range`, `gender`, `birth-region` and
  `school-region` are open-vocabulary columns (`OPEN_COLUMNS`): only placeholder
  values (`_`, `over 85`) are mapped and unmapped values are not reported.
* `tsv2vert_v2.py`: the `participants` column of `conversations.tsv` is no
  longer dropped; it is written as a comma-separated multivalue
  `<conversation participants="BO026,BO020">` attribute (registries declare it
  `MULTIVALUE "1"`, `MULTISEP ","`), so whole conversations can be selected by
  participant. The per-turn `participant_code` remains for selecting a
  participant's own turns.
* `tsv2vert_v2.py`: in a run with several input files each conversation code is
  written once — the first input file that has it wins, and later duplicates are
  reported on stderr (`skipping duplicate conversation …`). Needed for the
  aggregated `KIParla` corpus, where `TOD2001`–`TOD2016` are in both `KIP` and
  `ParlaTO`. List the preferred module first.
* `tsv2vert_v2.py`: `module_for_code` now also maps `BXA/BZA` → `ParlaBZ`,
  `SBC/SBI` → `Stra-ParlaBO` and `STC/STI` → `Stra-ParlaTO`, so `full_conversation`
  and `report_url` point at the right module in the aggregate corpus. For a
  corpus whose NoSketch name differs from the module name (`StraParlaBO` vs
  `Stra-ParlaBO`) pass `--artifacts-module`.
* `translate_metadata.py`: values are stripped of leading/trailing whitespace
  before translation (a trailing space in `3-Technicians ` in a source table
  broke the lookup and leaked into the vertical file).
* `generate_registry_draft.py`: no longer excludes `participants`; it is
  emitted as a multivalue conversation attribute labelled "Partecipanti", and
  the draft no longer emits `NESTED 1` on `transcription_unit` (units never
  nest).

* `tsv2vert_v2.py`: each `<transcription_unit>` now carries a `report_url`
  attribute — a prefilled "open a GitHub issue about this turn" link targeting
  the conversation's module repository (`--issues-base-url`, default
  `https://github.com/KIParla`; pass `""` to disable). The corresponding
  `report_url` `MAXLISTSIZE "0"` attribute was added to the KIParla registry
  files.
* `tsv2vert_v2.py`: `--translations-dir` (auto-detected from a sibling
  `translations/` directory) adds a `translation` structure attribute to each
  transcription unit that has a translation-tier rendering, matched by
  `parent_tu_id`.
* `tsv2vert_v2.py`: token lines now carry `lemma` and `upos` as positional
  attributes 3–4 (from the source TSV, empty when absent), and each
  `<conversation>` gets `linguistic_annotation="yes"/"no"`. The KIParla
  registry files gained the matching `ATTRIBUTE lemma` / `ATTRIBUTE upos`
  positional entries, a `linguistic_annotation` conversation attribute, and
  that attribute in `SUBCORPATTRS`.
* `tsv2vert_v2.py`: short pauses (`(.)`) and non-verbal behaviour (`((…))`) are
  emitted as zero-width `<pause/>` / `<nvb descr="…"/>` tags instead of tokens,
  so they no longer break token adjacency (`the (.) dog` still matches
  `"the" "dog"`). Registries gained `STRUCTURE pause` and `STRUCTURE nvb`. A
  turn that is only pause/NVB keeps the marker but loses its (now empty)
  `<transcription_unit>` wrapper. A run of consecutive markers (across turn
  boundaries too) is collapsed to at most one `<pause/>` and one
  `<nvb descr="a; b">` — two same-type zero-width structures at one position
  would otherwise be dropped by the indexer. `nvb` `descr` keeps `_` for spaces
  (a registry `DISPLAYBEGIN` cannot render a value with spaces); the markers
  show in the concordance as `·(.)·` / `·((descr))·`. A word that was glued
  (`SpaceAfter=No`) to a now-removed marker no longer emits `<g/>`.
* `tsv2vert_v2.py`: a speaker with no `participants.tsv` row (`???`, `??`, an
  unlisted code) now gets every `participant_*` attribute set to `N/A` instead
  of unset (NoSketch was showing the `===NONE===` sentinel).
* `WORD_CORRECTIONS`: added `ceh` → `c(io)è` and `mmh` → `mhmh`. Each
  occurrence is reported as a `WORD_CORRECTIONS` warning like the existing
  interjection spellings.
* new `vert2eaf-layered` command (`tsv2eaf_layered.py`): renders a `.vert.tsv`
  to a layered ELAN `.eaf` with a per-speaker tier hierarchy named in the
  Toolbox/ELAN interlinear `<code>@<speaker>` convention — `ref@` (units) ▸
  `ft@` (translation), `tx@` (enriched), `tx_ortho@` (orthographic) ▸ `tok@`
  (tokens) ▸ `nvb@`, `sent_id@` (many-to-many syntactic-sentence link) and,
  with `--linguistic`, `lemma@ / pos@ / xpos@ / feats@ / dep@`. Empty leaf
  tiers are pruned; `--template` writes an `.etf` with the full tier set for
  every speaker. `process` now also emits both a plain (`eaf/`, one tier per
  speaker) and a layered (`eaf_layered/` + `<module>.etf`) rendering of every
  conversation, unless `--no-eaf`.
* reworked NVB/shortpause overlap handling into two clearly separated concerns:
** **Bracket-edge position** (`switch_NVB` in `normalize.py`): an NVB tag or
   shortpause `(.)` immediately after `[` or before `]` now *always* stays in
   place, unconditionally — `nvb_participates_in_overlaps` no longer has any
   effect here (the parameter was removed from `switch_NVB` and
   `validate_and_normalize`). Previously NVB was relocated out of `[...]`
   unless the flag was set; shortpause was already always kept.
** **Token-feature encoding** (`TranscriptionUnit.add_token_features` in
   `data.py`): NVB and shortpause tokens now correctly get an `overlaps`
   feature at all when they genuinely sit inside a matched overlap span —
   previously they were entirely invisible to the character-to-token mapping
   (every character of `((laugh))`/`(.)` is a bracket/dot marker, i.e. has no
   "form character" under that mapping's definition, so it silently never
   matched). Since NVB/shortpause can never be interrupted by `[`/`]`
   mid-marker (unlike ordinary tokens, which can straddle an overlap
   boundary mid-word), a char range doesn't mean anything for them either:
   detected via the token's own character span rather than the letters-only
   index, and rendered in the `overlaps` column as the sentinel `X(id)`
   (e.g. `((ride))` → `X(0)`) instead of a `cs-ce(id)` char range — same
   convention as their `upos` value. Every existing downstream consumer of
   this column (`tsv2tei.py`, `tsv2chat_bak.py`, `make_patch.py`) only ever
   extracts the id via `\((\d+)\)`, so `X(id)` is a drop-in match.
** **TU/clique-level participation** (`Transcript.check_overlaps` in
   `data.py`): removed the old step 6a that pruned every graph edge touching
   an NVB/shortpause-only TU *before* cliques were even built — that meant a
   genuinely annotated `[...]` overlap on such a TU (and its overlap partner)
   lost its match entirely and fell through to an `OVERLAPS:MISSING_TIME`
   error with a `"?"` placeholder instead of a real feature. Now every edge
   survives into clique-building regardless of token type, so an annotated
   NVB/shortpause overlap always gets matched and featured correctly.
   `overlaps.nvb_participates_in_overlaps` now controls exactly one thing:
   whether an *unannotated* overlap event involving only NVB/shortpause
   tokens counts as removable noise (`false`, default) or as a genuine
   overlap that should have been annotated (`true`, now an
   `OVERLAPS:MISSING_ANNOTATION` error). Shortpause is assimilated to NVB
   here, gated by the same toggle.
* added an Antora documentation component for `tools`
* documented the standalone scripts with concrete command examples
* documented the test workflow
* added unit tests for the importable script logic
* refactored `tsv2eaf.py` so it can be imported and tested safely
