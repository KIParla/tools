= Variation labels in the vert.tsv

The variation markers of the enriched transcription (`#word`, `#*word`, `$word`, `#_`,
and a unit-initial `# `) are exported in a single feature-list column of the
`.vert.tsv`, `code-variation`, and to NoSketch Engine as the attributes `variety`, `nonce` and
`contains_variation`. This page describes the format and how it differs from the one used
before; it is a *breaking change* of the vert.tsv schema.

== The `code-variation` column

`code-variation` holds every variation feature of a token as pipe-separated `Key=Value` pairs
(CoNLL-U style). None of them is in `jefferson_feats`.

[cols="2,3", options="header"]
|===
| Feature | Meaning

| `ContainsVariation=Yes\|No`
| Unit level, repeated on every token row of the unit. `Yes` when any token of the unit has
  a `Code`. Always present, so the column is never empty. A `$` form alone does not make
  it `Yes`.

| `Code=Other`
| `#word`, or any token covered by a `#_` marker: from the marker to the end of the unit
  (the whole unit when the marker is unit-initial).

| `Code=Unsure`
| `#*word`: the code of the token can be assigned to more than one language (e.g. Italian
  and Spanish).

| `Code=Underspecified`
| A token of a unit that starts with `# `: at least one word of the unit belongs to another
  language, but the transcriber did not say which. An explicit `#word` / `#*word` in such a unit keeps its own label.

| `Language=<ISO code>`
| On tokens marked `Other` or `Unsure`; `NO_ISO_CODE` when the language was not
  identified. Not set on `Underspecified` tokens (the language is unknown).

| `Nonce=Yes`
| `$word`: a nonce or non-standard form. It is a property of the form, not a code change, and
  is independent of `Code`.
|===

Examples:

----
ContainsVariation=No
ContainsVariation=Yes
ContainsVariation=Yes|Code=Other|Language=NO_ISO_CODE
ContainsVariation=Yes|Code=Underspecified
ContainsVariation=No|Nonce=Yes
----

Pauses, non-verbal behaviour, anonymized names and `xxx` never carry a code.

== Everything is recoverable from `span`

The unit-initial marker is part of the `span` of the unit's first token (`# hola`,
`#_ hola`), and a mid-unit `#_` is part of the span of the first token it covers
(`#_ l-ʕars`). The enriched text, the EAF rebuilt by `vert2eaf` and the linear files are
therefore rebuilt from `span` alone and match the transcription exactly; the unit-level
`ContainsVariation` flag is not needed for that.

In the NoSketch vertical only the labels are available. `other`, `unsure` and `nonce`
words map back to `#`, `#*` and `$`, and `underspecified` words to a unit-initial `# `. What a
vertical cannot tell is the notation used for `other`: a `#_` stretch and the same words each
marked with `#` are the same data.

== Differences from the previous format

[cols="1,1", options="header"]
|===
| Before | Now

| Column `variation`: one label per unit — `none`, `yes`, `unspecified` (a `# ` unit),
  `all` (a `#_` unit); older files have `some`
| Column `code-variation`: the feature list above. How a unit was written (`# `, `#_ `) is read
  from the spans

| `jefferson_feats`: `Variation=Token`
| `code-variation`: `Code=Other`

| `jefferson_feats`: `Variation=Doubtful`
| `code-variation`: `Code=Unsure`

| `jefferson_feats`: `Variation=Emerging` and `Orthography=Yes` (`$word`)
| `code-variation`: `Nonce=Yes`

| `jefferson_feats`: `Language=<code>`
| `code-variation`: `Language=<code>`

| Tokens of a `# ` unit: no token-level information
| `code-variation`: `Code=Underspecified`

| `span`: a unit-initial `# ` / `#_ ` was not in any span (it was rebuilt from the unit label)
| `span` of the first token starts with the marker

| NoSketch positional `variation`, `non_standard_form`; unit attribute `language_variation`
| NoSketch positional `variety`, `nonce`; unit attribute `contains_variation`

| `csv-metadata.json`: describes the old column
| Regenerated from the updated `csvw/vert-schema.json`
|===

The number of columns is unchanged.

== Migrating

The tools refuse to read an old-format file (`variety.iter_vert_rows` raises
`old-format vert.tsv`): its unit-initial markers are not in the spans, so reading it would
silently lose them. There is no in-place converter, because the EAF is the source of truth:

. Regenerate each module from its `.eaf` files: `python sync.py --from-eaf <module>/eaf/X.eaf`
  (this rewrites `tsv/`, `translations/`, `linear-enriched/` and `linear-orthographic/`).
. Regenerate each module's `csv-metadata.json`: `python csvw/generate_csvw.py <module_dir>`.
. Regenerate the validation pages (`generate_validation_report.py`).
. Rebuild the NoSketch corpora together with their registries (`KIParla-NoSketch-Data`).
. Release each already-released module with a **major** version: the schema, the
  `csv-metadata.json` and the NoSketch attributes change. A module that has not been
  released yet ships the new format as its first release.

== Renaming to `code-variation`

The column was first released as `variation` with the feature `Variety=Other|Unassignable|Unsure`.
It is now `code-variation` with `Code=Other|Unsure|Underspecified`, because the features describe
code switching and nonce formations rather than varieties:

[cols="1,1", options="header"]
|===
| Before | Now

| Column `variation`
| Column `code-variation`

| `Variety=Other`
| `Code=Other`

| `Variety=Unassignable` (`#*word`)
| `Code=Unsure`

| `Variety=Unsure` (tokens of a `# ` unit)
| `Code=Underspecified`
|===

`ContainsVariation`, `Language` and `Nonce` keep their names.
